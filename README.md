# เฝ้าระวังน้ำไทย

เว็บข้อมูลจริงจากแหล่งสาธารณะ แสดงเวลาตรวจวัดแยกจากเวลาที่ดึง API หน้าแรกจัดจุดถึงเกณฑ์ก่อนและเรียงข้อมูลล่าสุด ใช้แผนที่ OpenStreetMap และรองรับมือถือ

## รันเว็บ

```sh
npm install
npm run dev
# production
npm run build
npm start
```

เปิด http://localhost:3000 ใช้ Node.js 22.13 ขึ้นไป ข่าวและกล้องตรวจทุก 60 วินาที ข้อมูลทั่วไป 120 วินาที เมื่อเปิดแท็บอยู่ เซิร์ฟเวอร์ cache ผลจริง 60 วินาทีและรวมคำขอต้นทางที่ซ้ำกัน หน้าเว็บแสดงผลทีละ feed โดยไม่รอให้ครบทุกแหล่ง

### macOS: เปิด dev แล้วขึ้น `ECANCELED: operation canceled, read`

หากโปรเจกต์อยู่ใน Desktop ที่ซิงก์กับ iCloud ให้คลิกขวาโฟลเดอร์ `thai-water-monitor` ใน Finder แล้วเลือก **Keep Downloaded** และรอให้ดาวน์โหลดครบ ไฟล์ที่ `ls -lO` แสดง `dataless` ยังไม่มีเนื้อหาอยู่บนเครื่อง จึงอาจทำให้ Node อ่านค้างหรือถูกยกเลิกได้

หากไฟล์ใน `node_modules` ยังอ่านไม่ได้ ให้หยุดเซิร์ฟเวอร์แล้วรัน `npm ci` เพื่อติดตั้งตาม lockfile เดิม; ใช้ `npm ci --offline --no-audit --no-fund` ได้เมื่อแพ็กเกจทั้งหมดมีในแคชแล้ว หาก dev ขึ้น Ready แต่หน้าเว็บค้างจาก cache เดิม ให้หยุดเซิร์ฟเวอร์และเปลี่ยนชื่อ `.next/dev` เพื่อเก็บสำรอง ก่อนรัน `npm run dev` ใหม่ ห้ามลบ `data/community` ซึ่งเก็บรายงานและรูปจริง

รัน dev หรือ production เพียงหนึ่งตัวบนพอร์ต 3000 หากต้องการเปลี่ยนพอร์ต dev ใช้ `npm run dev -- --port 3001`

## แหล่งที่เชื่อมแล้ว

- ThaiWater: แม่น้ำ คลอง อัตราการไหล ประตูน้ำ ฝน ถนน รายการ CCTV และพายุ
- สำนักการระบายน้ำ กทม. ผ่าน POPNIX Flood: คลองพร้อมแนวโน้มเทียบ 60 นาที ถนน น้ำขึ้นลงปากเจ้าพระยา แม่น้ำเจ้าพระยา/แนวโน้ม อัตราการไหล/ความเร็วกระแสน้ำ และฝนรอบ กทม. ดัชนีกล้องจราจร/ระบายน้ำ ตรวจ stale และเวลาภาพก่อนแสดง
- MAHOLAN CCTV: ดัชนีสตรีมสาธารณะ HLS/MJPEG และภาพย่อ กล้องที่โหลดภาพไม่สำเร็จซ่อนจากรายการ ตัวเล่นโหลดเมื่อเปิดกล้อง
- FEWS: ตารางคาดการณ์ระดับทะเล แสดงเฉพาะเมื่อมีวันที่วันนี้
- กรมประชาสัมพันธ์ JSONFeed และกรมอุตุนิยมวิทยา CAP: พาดหัว/ประกาศย้อนหลังไม่เกิน 3 วัน ลิงก์อ่านต้นฉบับ ตรวจทุกนาที ไม่แปลว่าแหล่งเผยแพร่ข่าวทุกนาที
- Windy official embed: เรดาร์ ฝนพยากรณ์ และลม แยกจากค่าของสถานีตรวจวัด

ไม่มี mock data และไม่ใช้ไฟล์ snapshot แทนข้อมูลเมื่อ API ล่ม เวลาวัดเกิน 6 ชั่วโมงไม่ถูกนับเป็นจุดเตือนปัจจุบัน ภาพกล้อง กทม. ต้องใหม่ไม่เกิน 15 นาที จำนวนกล้องในดัชนีไม่ใช่การรับประกันว่าเปิดสตรีมได้ทุกตัว

## รายงานประชาชนและรูป

ฟอร์มบันทึกพิกัด รูป และข้อความลง MongoDB จริง พร้อมอัปเดตข้อความ/รูปต่อจุด รูป JPG/PNG/WebP ไม่เกิน 4 MB ถูกย่อและลบ metadata เก็บเป็น BSON Binary ใน MongoDB โดยไม่เขียนลงดิสก์ Vercel รายงานระบุว่า **ยังไม่ผ่านการยืนยัน** และไม่ส่งต่อถึงหน่วยงานอัตโนมัติ โทร 1784 สำหรับเหตุฉุกเฉิน

### ตั้งค่า MongoDB Atlas และ Vercel

1. สร้างฐานข้อมูลใน MongoDB Atlas และ database user ที่มีสิทธิ์ `readWrite` เฉพาะฐานข้อมูลนี้ ให้ตั้ง Network Access สำหรับเครือข่ายที่เซิร์ฟเวอร์จะเชื่อม
2. เลือก **Connect → Drivers → Node.js** แล้วคัดลอก connection string (`mongodb+srv://...`) สิ่งที่เว็บต้องใช้คือ connection string พร้อมชื่อผู้ใช้/รหัสผ่านฐานข้อมูล ไม่ใช่ Atlas Management API key หากรหัสผ่านมีอักขระพิเศษ ต้อง URL-encode
3. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ `MONGODB_URI` และ `MONGODB_DB_NAME` (ค่าเริ่มต้น `thai_water_monitor`) อย่าใส่ `NEXT_PUBLIC_` และอย่า commit ไฟล์นี้
4. รัน `npm run db:check` เพื่อตรวจการเชื่อมต่อและสร้างดัชนี แล้วรีสตาร์ต `npm run dev`
5. บน Vercel เพิ่มสองตัวแปรนี้ใน **Project → Settings → Environment Variables** ให้ตรงกับ environment ที่ใช้งาน แล้ว deploy ใหม่ ใช้ฐานข้อมูลแยกสำหรับ Preview กับ Production เพื่อไม่ให้โพสต์ทดสอบปะปน

ไม่มีการเชื่อมต่อฐานข้อมูลระหว่าง build; API เชื่อมเมื่อเรียกใช้งาน และใช้ connection pool ซ้ำสูงสุด 10 connections ต่อ instance ถ้ายังไม่ได้ใส่ URI หน้าแผนที่และ API ภายนอกยังใช้ได้ ส่วนรายงานตอบ `503` และปุ่มส่งรายงานจะปิดเมื่อโหลดรายงานไม่ได้ ไม่มีข้อมูลจำลองหรือการบันทึกลง SQLite แทนอย่างเงียบ ๆ

Collections: `reports` เก็บโพสต์/พิกัด GeoJSON/รูป, `report_updates` เก็บอัปเดตต่อจุด/รูป และ `report_limits` เก็บตัวนับป้องกันการส่งถี่ร่วมกันทุก instance พร้อม TTL ลบตัวนับหมดอายุ จำกัด 8 ครั้งต่อ IP ต่อช่วง 15 นาทีแบบ fixed window รายการรายงานไม่ดึง bytes ของรูป จึงไม่ทำให้หน้าแผนที่โหลดรูปทั้งหมด

รูปที่เก็บใน MongoDB เพิ่มการใช้พื้นที่ฐานข้อมูล ควรติดตาม quota/backup ของ Atlas และเพิ่มระบบตรวจสอบ/ลบรายงานก่อนเปิดใช้วงกว้าง ตอนนี้ยังไม่มีบัญชีผู้ใช้และหน้าจัดการรายงานของผู้ดูแล

### ย้ายข้อมูล SQLite เดิม (ถ้ามี)

ไฟล์เดิม `data/community/reports.sqlite` ยังเก็บไว้ ไม่ถูกแก้หรือลบ และไม่ถูกใช้โดย API ใหม่ ตรวจจำนวนก่อนด้วย `npm run db:migrate:sqlite -- --dry-run` หลังตั้งค่า MongoDB ให้รัน `npm run db:migrate:sqlite` เพื่อย้ายโพสต์ รูป และอัปเดตพร้อม UUID เดิม รันซ้ำได้โดยไม่เขียนทับรายงานที่มีใน MongoDB แล้ว หากฐานข้อมูลเก่าอยู่ที่อื่น ส่งพาธ `.sqlite` ต่อท้ายคำสั่ง ต้องสำรองไฟล์เดิมไว้จนตรวจข้อมูลที่ย้ายครบ

เอกสาร: [MongoDB connection pools](https://www.mongodb.com/docs/drivers/node/current/connect/connection-options/connection-pools/), [ข้อจำกัดขนาดเอกสาร BSON](https://www.mongodb.com/docs/manual/core/document/)
